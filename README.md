# 视频拆解工具箱

把"拆解一个视频的写法 → 仿写出自己的稿子"这件事变成一条能重复跑的流水线。

建立日期：2026-09-22（首次跑通：影视飓风 6 条 + 王局 2 条 + 正确君 1 条）

---

## 一、这套东西解决什么问题

看到一条好视频，想知道"它为什么抓人"，然后写出同款。

难点有两个：
1. **有风险的素材不能全读**（读多了会触发模型侧内容风控，会话会被掐断）
2. **光靠感觉拆不出可复用的东西**

这套流程的答案是：**研究结构，不研究内容**。

---

## 二、六步流程

### 第 1 步：拿素材

```bash
# 需要代理（Flow：SOCKS 10606 / HTTP 10607）+ YouTube 登录 cookie
yt-dlp --proxy http://127.0.0.1:10607 --cookies cookies.txt \
  -f "18/best[height<=480]/best" \
  -o "video/%(id)s.%(ext)s" "https://www.youtube.com/watch?v=<ID>"
```

### 第 2 步：抽音频 + 转写

```bash
ffmpeg -v error -y -i video/<ID>.mp4 -vn -acodec pcm_s16le -ar 16000 -ac 1 audio/<ID>.wav

cd ~/.claude/skills/aliyun-audio-transcribe
python3 scripts/transcribe.py "<绝对路径>/audio/<ID>.wav" --output-dir "<绝对路径>/transcript"
```

费用约 0.288 元/小时。产出 `<ID>.txt / .srt / .json`。

### 第 3 步：量化指标（安全）

```bash
python3 metrics.py transcript/
```

出语速、句长、停顿对比表。

### 第 4 步：结构探针（安全，核心步骤）

```bash
python3 probe_structure.py transcript/ other_transcript/
```

出问句密度、推进词密度、提问峰值时段。

**这一步是"为什么能一直看下去"的答案来源。**

### 第 5 步：定点抽读（只读 10%–15%，关键）

先用探针找到"提问峰值"在哪几分钟，然后：

```bash
# 开头 90 秒 + 提问峰值段 + 结尾 60 秒
python3 extract_segments.py transcript/<ID>.srt 0:00-1:30 18:00-20:00 28:50-29:54
```

打开生成的 `_抽读_<ID>.txt` 读——**只看这三段**，就能拿到钩子写法、中段推进、收尾设计。

> 实测：正确君那条 29.9 分钟的视频，只读 1548 字（14.7%）就拿到了全部核心手法。
> 王局样本 1（30 分钟）只读 1382 字（15.2%）。

### 第 6 步：仿写 + 交付

按提炼出的风格骨架写稿，交付成 TXT 放 iCloud（见第五节）。

## 三、安全须知（重要）

**"内容风控"拦的是装进上下文的东西，不是模型选择。**

- 报错特征：`400 Content Exists Risk`（国产 API 风控）/ `xxx can't help with this`（模型端 refusal）
- 换模型解决不了根因；**规避审核的事不做**
- 正确做法：**素材去载荷、保结构**

三条硬规矩：

1. **本地算、只喂数字** —— 指标和探针输出全是虚词和数字，正文留在本地脚本里
2. **敏感素材不全读** —— 用 `extract_segments.py` 定点抽读
3. **敏感文件隔离** —— 全文转写用完就删/移走（音视频保留，可随时重转，约 0.29 元/小时）

## 四、三种风格骨架（可直接套）

这三套是从 9 条中文样本里提炼的，对应三种完全不同的留人机制。

### A. 王局式 —— 靠"追问"留人

```
第一人称介入 → 耸动论断 → 自问自答追问链 → 讲一半刹车 → 重复重锤收尾
```

- 招牌句式：**"那 + 某某 + 有什么用呢？"**，同一句式反复敲
- 观众不是被悬念留住的，是被**追问带着走**的：每 15 秒问一次，观众心里跟着答一次
- 适用：观点、澄清、强人设
- 数据特征：问句 2.0/分（最高），"但是"多于"所以"（转折驱动）

### B. 正确君式 —— 靠"密度 + 类比"留人

```
第三人称冷叙述 → 开头塞满信息点 → 类比链 → 因果推进 → 荒诞画面收尾
```

- 开头 90 秒塞 7 个信息点（时间/数字/信源/人物/悬念）
- **抽象概念一律落地成类比**（频谱→"比一块地还高"；规则→"先占坑但得真盖房子"）
- 收尾用画面、不解释（"真正的马斯克看了一眼，买张机票走了"）
- 数据特征：语速 350 字/分，"所以"多于"但是"（因果驱动）

### C. 影视飓风式 —— 靠"温度 + 金句"留人

```
反预期钩子 → 全程第二人称"你" → 具体数字 → 转折自曝 → 金句升华收尾
```

- **每 2–3 句一个"你"**（最稳定的特征）
- **抢答质疑**："你可能会想：什么都做，是不是什么都不精？这个问题你问得好。我也怕。"
- 收尾先给情绪、最后才放名字，从不喊"欢迎咨询"
- 数据特征：短内容语速快（370+），长内容大量留白

## 五、交付规范（TXT / 手机阅读）

孙哥要把稿子导进手机阅读器，所以：

- **格式：纯文本 `.txt`，UTF-8，无 BOM**
- **绝对不能有 markdown 符号**（`**` `#` `|` 会在阅读器里原样显示，很难看）
- 排版：标题用 `====` / `----` 分隔线，段落之间空一行，短行易读
- 结构：每段 = 时间 + 画面描述 + 口播正文，最后附拍摄提示
- 落盘位置：`iCloud/口播文案/<项目名>/`
- 自检命令：
  ```bash
  grep -c -E '\*\*|^#|^\|' *.txt   # 应全部为 0
  ```

## 六、脚本清单

| 脚本 | 作用 | 是否安全（不读正文） |
|---|---|---|
| `metrics.py` | 语速 / 句长 / 停顿 / 说话人 | ✅ 纯数字 |
| `probe_structure.py` | 问句密度 / 推进词密度 / 提问峰值 | ✅ 只输出白名单虚词 |
| `extract_segments.py` | 定点抽读（只读 10%–15%） | ⚠️ 会输出指定片段原文 |

依赖：Python 3 标准库，无需安装第三方包。

## 七、实测数据基准（用于给自己片子定速）

| 片长 | 语速 | 句间停顿 | 长停顿（>2s） |
|---|---|---|---|
| 5–6 分钟 | 370–400 字/分 | 0.23–0.30 秒 | 0 处 |
| 9–16 分钟 | 290–320 字/分 | 0.28–0.35 秒 | 8–20 处 |
| 20 分钟以上 | 220–290 字/分 | 0.76 秒 | 30+ 处 |

**公式：字数 ÷ 语速 = 时长**。做 8 分钟观点视频 → 约 300 字/分 → 写 2400 字。

## 九、版本与升级机制

**当前版本：v1.0**（2026-09-22 首次跑通）

### 升级规矩

1. **每次用完，若有新发现就改这里** —— 踩了新坑、找到更好的参数，
   直接改脚本，并在下面的变更记录加一行。**不要另起炉灶。**
2. **脚本保持参数化** —— 不要写死路径、不要依赖某个项目目录。
3. **新增能力写成独立脚本** —— 不要改大现有脚本的接口，避免破坏已有用法。
4. **安全约束不能松** —— `probe_structure.py` 永远只输出白名单虚词和数字；
   `extract_segments.py` 是唯一会输出原文的脚本，用它时要清楚自己在读什么。
5. **无第三方依赖** —— 只用 Python 3 标准库，换台机器也能跑。
